## 2026-09-03 — Sprint E9.1: remove OCR, strengthen measure overlay, honest floor-area sourcing

Live testing showed real UK agent plans too rarely carry readable dimensions, so OCR is cut entirely and the effort redirected to the measure overlay + honest floor-area sourcing.

- **OCR removed.** Deleted `src/ocr.ts`, the vendored `public/tesseract/*` (wasm core + traineddata + worker), the `tesseract.js` / `tesseract.js-core` dependencies, and all OCR code paths in the panel (`startFloorPlanOcr`, the read/progress/failed states, the OCR-text parser `parseFloorPlan` and its `FloorPlanRead`/room-list types). **Package size: 264 KB (was ~5.7 MB).** With no wasm/worker left in the panel, the CSP is tightened back to `script-src 'self'; object-src 'self'` (no `wasm-unsafe-eval`, no `worker-src`). Kept the parser + room-fit + measure-geometry unit tests that still apply to manually-typed dimensions (metric/imperial/mixed/comma/ambiguous-bare, HMO minimums, scale/measure/rectangle).
- **Measure overlay is now the headline** of the floor-plan section: a card whose one line tells the user what to do ("Open the plan, drag along a dimension you can read to set the scale, then measure walls or drag a rectangle to test whether a room would fit"), opening the client-side canvas tool. Pointer-only drawing with a keyboard-accessible width × length form beside it; measuring works even on a CORS-tainted image (display-only, no pixel read). A measured total can be accepted as the floor area ("from the floor plan"); measured rooms can be recorded and flagged live against the 6.51 m² minimum.
- **HMO room-size — honest assumption, never a legality claim (item 3).** With no measurements the component reads "Assumed N lettable rooms from the listing. We can\'t see room sizes from a listing, so measure them before you commit — undersized rooms can\'t be let in a licensed HMO." (status unknown, doesn\'t claim compliance, doesn\'t block the score). If the user measures rooms with the overlay, THEIR figures are used and the copy says so ("From your measurements, X room(s) fall below the 6.51 m² minimum").
- **Floor area — investigated before building (item 4):**
  - **(a) EPC coverage is GOOD:** measured across a 400-sector / 30,404-sale sample of our R2 data, **84.9% of sales carry a floorAreaSqm** (median 94%/sector); 100% have a paon, 98% a street. So coverage is NOT the bottleneck.
  - **(b) The bottleneck is the ADDRESS on the listing:** Rightmove\'s `__PAGE_MODEL` exposes only a joined `displayAddress` (no separate house-number field — nothing is being discarded), and many are street-only, so ~2/3 of the Rightmove fixtures have no house number to match. Every listing DOES carry a full postcode. Best lever: match on **full postcode + paon** (the strongest key, mirroring the web\'s `epcArea.ts`) with the paon+street match as a fallback — implemented in `floorAreaFromSector(sector, address, postcode)`, matching across street-text differences and refusing ambiguous flats (same postcode/paon, differing areas ⇒ never guess).
  - **(c) EPC API at runtime: RULED OUT.** It needs a Bearer token, which in a client-side extension would have to ship in the public package — anyone could extract it. That violates CLAUDE.md (never expose secrets) and the extension\'s tight permissions, so it is a security non-starter.
  - **Real match rate:** where a listing has a full postcode + a house number (Zoopla almost always; a Rightmove listing that prints its number), the match now lands given 85% data coverage; street-only Rightmove listings genuinely can\'t be matched — for those the manual field is made **prominent** and **pre-explained** ("This listing doesn\'t give a floor area and we couldn\'t match it to an EPC record — enter it (or measure it on the plan) and we\'ll remember it"), and a missing area NEVER silently drives a £/sqm end-value suggestion (that path already requires a real area and labels its source).

Now a measured FAILURE is always authoritative (red), but an all-clear (0) is granted ONLY once every *assumed* lettable room has been measured; a partial all-pass stays the honest "assumed N rooms — measure them" (unknown). Regression cases added. (should) The measured room-size copy asserted flat compliance; it now always carries `ROOM_FIT_CAVEAT` ("an indication from your measurements, not a survey — floor under a 1.5 m ceiling doesn't count and some councils set higher minimums") so a pass is never read as legal clearance. (nits) The assumption copy no longer claims the room count came "from the listing" (it can be the config default) — now "Assumed N lettable rooms — check this figure…"; the measure screen's "N room(s) recorded so far" counter updates in place after each record (was stale); the stale `wasm-unsafe-eval` CSP claim was removed from the `wxt.config.ts` docblock; ~18 dead OCR-panel CSS rules were deleted and the live `.fp-head`/`.fp-prompt` classes given styles (+ `.floorplan-card` padding).

## 2026-09-03 — Sprint E9: offline floor-plan OCR, room-fit checks, measure overlay

The floor plan is often the only place the real dimensions exist (E8.2: ~2/6 Rightmove listings even carry a house number for EPC matching). This reads them locally.

- **Everything offline, image never leaves the device.** Tesseract.js 7 + its wasm core (`tesseract-core-simd-lstm.wasm`) + English `eng.traineddata.gz` are vendored under `packages/extension/public/tesseract/` and referenced via `chrome.runtime.getURL` (workerPath/corePath/langPath) — **no CDN, no runtime download**. OCR runs in the SIDE PANEL page (never the service worker); the plan image is drawn to a local canvas, preprocessed (greyscale, contrast, adaptive threshold, upscale) and recognised in place. Tesseract is lazy-imported so the verdict renders first and OCR only loads when the floor-plan section is expanded (item 6). The CSP already allowed `wasm-unsafe-eval` + `worker-src 'self'`, so no manifest change.
- **Package size delta ≈ 4.9 MB** (built extension 5.7 MB vs ~0.8 MB before): 2.7 MB wasm core + 1.9 MB gzipped traineddata + ~0.23 MB worker/loader + a small esm chunk. **Judgment call:** used the `fast` traineddata (gzipped, ~1.9 MB) not `best` (~15 MB) — digit-focused OCR doesn't need `best`, and £0/size matters.
- **Pure logic in core (`listing/floorplan.ts`), fully tested.** Parses BOTH conventions — metric ("3.50m x 4.20m", "3.5 x 4.2"), imperial ("11'6\" x 13'9\""), mixed ("3.50m (11'6\") …" → metric wins), and a bare-integer→feet heuristic ("11 x 13") — converts to m² and ft², extracts room names, and grades each room high/medium/low. Honesty is structural: an implausible parse (a 0.02 m² or 400 m² "room") is DROPPED as noise, never shown; the total is labelled "sum of N rooms we could read", NEVER GIA; a cross-check flags reading HIGHER than a known floor area (OCR misread) or only a fraction; if nothing reads, it says so and offers manual entry.
- **HMO room-fit (England statutory minimums 4.64 / 6.51 / 10.22 m²).** Per-room fit + a count of rooms meeting the single-adult 6.51 m² minimum, with the plain caveat that floor under 1.5 m ceiling is excluded (we can't see heights) and councils (esp. London) often require more — an indication from a plan, not a survey. It feeds the HMO score's room-size component ONLY when we can identify named bedrooms at good confidence (`roomSizeFailures`); otherwise the component stays "check in the analyser" as before.
- **Measure / reconfigure overlay (item 4):** a client-side canvas — drag along a known dimension to set the scale (pre-filled from a high-confidence OCR'd dimension), then measure a wall or drag a rectangle to test "would a bedroom fit?", flagged against the 6.51 m² minimum. Canvas dragging is pointer-only, with a keyboard-accessible width × length form beside it (stated plainly). Geometry is pure + tested; measuring works even on a CORS-tainted image (display only, no pixel read).
- **Feeds outward (item 5):** an accepted OCR total or a measured area becomes the floor-area input, labelled "from the floor plan", flows into scoring and the analyser handoff; every room value is one-tap editable and a corrected value is marked as the user's.
- **Judgment call — CORS/permissions honesty:** reading a portal-CDN image's pixels needs a CORS-clean canvas; the image loads with `crossOrigin="anonymous"`, and if the CDN doesn't allow it the canvas taints and OCR fails cleanly to manual entry (never a wrong number). Zoopla plans are on `lid.zoocdn.com` (outside host_permissions) — an `<img>` still displays (so the MEASURE tool works) but pixel OCR may be blocked; this is surfaced honestly, not hidden.
- **Judgment call — output guard:** the bundled tesseract carries inert default CDN URLs (jsdelivr/github/opencollective) as string literals; we override every path to local `getURL`, so they are never fetched. The build guard now bans web-font CDNs and portal hosts ABSOLUTELY everywhere and for OUR code still forbids any new external host, but exempts the tesseract vendor/bundle strings while ASSERTING our OCR supplies local worker/core/lang paths and that the files ship locally — so the "no network load" guarantee is kept, honestly.
- **HONEST ACCURACY — the important caveat:** real-plan OCR accuracy could NOT be measured in this headless session — there is no browser, no node-canvas, and no real UK agent plan images in the repo, so the wasm OCR pipeline cannot be run end-to-end here. What IS verified: the parser/room-fit/measure logic is exhaustively unit-tested (17 core tests) on realistic OCR strings and passes; the engine files are the standard tesseract.js v7 offline set wired per the documented pattern; and the fallbacks (drop-implausible, "we couldn't read it", editable rows, manual entry) guarantee no wrong number is ever shown. The operator must verify real-plan accuracy in the LOADED extension and decide keep/downgrade/cut (item 7); the feature is built so a poor read degrades to honest manual entry rather than a wrong figure.
- **Adversarial review fixes (17-agent verify workflow, before commit; 4 must-fix, all fixed).** (must) A numbered room label on a unit-less line was parsed AS the width ("Bed 4 2.5 x 2.0" → 4×2, not 2.5×2.0) — a silent wrong number; the label/room-number is now stripped from each side BEFORE parsing, so the read text and the computed area always agree. (must) The bare-integer→feet flip only fired above the 90 m² plausibility ceiling, so feet-sized rooms in the 40–90 band surfaced as huge metric rooms at high confidence (an undersized bedroom silently passing the HMO check) — now it compares BOTH interpretations and, when metres and feet are both plausible, refuses to guess and falls back to manual (never a wrong number). (must) The OCR char-whitelist stripped ALL letters, so room names could never be read and the HMO bedroom feed could never fire — letters are back in the whitelist.
